# Kitsune Brewing Co. working agreements

## Scope and preservation

- For frontend work, preserve existing backend structure, behavior, integrations, stored data, and features unless the user explicitly requests changes.
- Preserve unrelated and uncommitted work. Inspect the current project before editing.
- Do not publish or deploy a redesign unless publishing is authorized by the user.

## Design quality

- Inspect the existing rendered experience before changing its design.
- For substantial redesigns, research Kitsune Brewing Co., its owner, and its audience using reliable sources. Translate verified findings into specific design decisions; do not invent brand facts.
- Use www.kitsunebrewingco.com only to read text for factual information. Do not use its page structure, navigation, layout, UI, or visual styling as design references. This restriction also applies to older project documents that mirror that website; inspecting the current project for functionality does not make its design an approved reference.
- Establish a coherent direction for composition, typography, imagery, spacing, color, and interaction. Do not equate polish with added decoration.
- Use the user's approved references and decisions as the design target. Keep a concise project design brief when substantial design work establishes new decisions, and distinguish proposed directions from approved ones.
- Preserve the requested scope while completing responsive layouts, accessibility, and relevant interaction states.

## Required verification for UI changes

- The user explicitly requests browser testing and visual inspection for UI changes. Inspect rendered screenshots at desktop and mobile sizes.
- Critique the result against the brief and references. Fix concrete weaknesses, then inspect the affected views again.
- A successful build is not evidence of visual quality. Verify both the implementation and the rendered result.
- For major redesigns, use an independent reviewer subagent to identify visual and usability problems. Evaluate and address its findings.
- If visual inspection or another necessary check is unavailable, state what remains unverified. Never claim a check happened when it did not.
- Deliver a working preview and representative screenshots, with a brief account of checks and remaining limitations.

## Collaboration

- Prioritize quality, correctness, and completeness over speed while staying within the requested scope.
- Make reasonable implementation decisions autonomously. Ask only when the answer materially affects direction, scope, or an irreversible action.
